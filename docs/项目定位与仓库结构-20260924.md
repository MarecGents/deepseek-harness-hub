## 一、远端结构

| remote | fetch | push | 用途 |
|---|---|---|---|
| `origin` | `dustinmoon78/deepseek-harness-hub` | 新仓 **+** `MarecGents/deepseek-harness-hub`（双 push url） | 日常开发线（`dev-v3` 等） |
| `own` | `dustinmoon78/deepseek-harness-hub` | 同 fetch | 只属本仓的操作（`main`、tags） |
| `fork` | `dustinmoon78/marec-dsh-desktop` | 同 | 历史 fork（旧仓名），勿再使用 |

MG 仓保留为**镜像**（可选，方便上游哪天回归时直接接手）：双推让两边 commit hash 天然一致，
不存在同步脚本与漂移。

## 二、日常纪律

1. **开发分支只有 `dev-v3`**；`git push origin dev-v3` 一条命令双远端同落
   （同一批提交 → hash 两边天然一致）。
2. push 输出**会出现两段结果**（新仓一段 + MG 一段）；只看到一段 = 少推一边，当场补推。
   若哪天不想再镜像 MG，摘掉 origin 的第二个 push url 即可（`git remote set-url --delete --push`）。
3. `main` 与 tags 走 `own`：`git push own main` / `git push own --tags`。
   本仓 `main` **不再受保护、可直接推送**（与 MG 侧不同）。
4. 分支删除同样走 `git push origin --delete <branch>`（自动双删，保持对称）。
