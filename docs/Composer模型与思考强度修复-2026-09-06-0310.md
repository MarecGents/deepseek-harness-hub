# Composer 模型与思考强度修复-2026-09-06-0310

## 任务概述

- 用户反馈：右下角模型选择仍使用官方默认 seat；自定义模型只有 Default 思考强度；此前将配置入口错误放进独立设置页。
- 目标：恢复历史 PR #33 的 composer 默认 seat；模型与思考强度位于同一个对话输入框右下角交互位置；自定义模型可在同一 Effort 面板声明档位；移除设置页插件。
- 基线：dev-v2，v0.1.6，dsh 0.1.2-rc.1。

## 调研与根因

1. 本地历史 ref `origin/pr-33` / `1d2ea233440e7d238909bbfc6478526ce101cc8d` 确认：`src/client/model-select.tsx` 原始功能就是替换 `conversation.input.model` composer seat，采用 provider→model 菜单与 effort pane；不是 settings section。
2. 官方 rc.1 `InputBar` 在 `conversation.input.model` 渲染；官方 ModelSelect 为单一 trigger，显示“模型 · 思考强度”，root pane 为 Model/Effort 两行；官方 seat priority=0，静态 hub priority=-1 才能 shadow。
3. `8243f84` 为避免顶层 `modelDirectories` 注入拖垮整个插件，改用 apply-time `ctx.get`；dsh rc.1 服务排序变化时可能在 apply 阶段尚未提供，导致静默 return，官方 seat 留存。当前修复改为 scoped `ctx.inject(['modelDirectories'])`。
4. 自定义模型没有 reasoning metadata 时，官方 catalog 不返回 efforts；前端硬编码档位会在 Host `UNSUPPORTED_REASONING_EFFORT` 校验处失败。正确路径是通过官方 settingsScope 写 `llm-pi-ai.reasoningEfforts`，再由 Host catalog 返回正式档位。

## 实施内容

- `src/client/model-select.tsx`：
  - 单一 composer trigger，符合官方默认位置；模型/思考强度共用同一向上弹层，root 为 Model/Effort 两级菜单。
  - 保留静态 hub `priority:-1`。
  - scoped `ctx.inject(['modelDirectories'])`，直接 `slots.inject`，移除多余外层 effect。
  - 成功选择增加 rejection handling；无 reasoning metadata 时不伪造正式 efforts，而在同一 Effort pane 提供“启用标准思考强度”入口。
  - inline 配置通过官方 `settingsScope` 写 `llm-pi-ai`，revision 校验后重新加载共享 directory；正式选择仍调用 `directory.select`。
- 删除 `plugins/dsh-model-efforts/` 整个设置页插件（该插件只在 1e4518f 引入）。
- `scripts/assemble-profile.mjs`：升级时只精确移除旧 `@dsh-external/dsh-model-efforts` bundle/junction，不扫描或删除其他插件/用户数据。
- 同步 `AGENTS.md`、`src/client/AGENTS.md`、`README.md`、`FUNCTIONS.md`、`docs/关键踩坑记录.md`、`docs/打包记录.md`；清理旧 settings.plugin.item 文案。
- 重新生成 `lib/client.js` 与 source map；安装 release resources 只保留 4 个独立插件。
