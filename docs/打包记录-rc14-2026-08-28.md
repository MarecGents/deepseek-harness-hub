## 本版内容（相对 rc.13：permission-guard 联动官方预设 + 权限策略 UI 融合）

### 背景根因（交叉调研，踩坑 #89 续）
dsh 官方权限管线 `pre-execute → approval → guards` 中，permission-guard 插件的 guard 挂在最后，只看自己的 `permission-guard.json`、不读会话官方 preset/sandbox/approval——`danger-full-access`（Full Access）与官方确认都过不了插件层（会话实测：Paper1 六次 write 全被拦，含切 Full Access 后）。

### 插件（dsh-permission-guard）
- **策略档位**（`permission-guard.json` 顶层 `policy`，默认 `follow`）：
  - `follow`：跟随会话官方 preset——`danger-full-access`（sandbox=danger-full-access 或 approval=never）→ 除 never 红线外全部放行；`read-only` → 只放行只读；`workspace-write` → 四级白名单
  - `strict`：始终按四级白名单拦截，不跟随 preset
  - `read-only`：无条件只放行只读操作
- **guard 联动**：`exec.agent.session.events` 折叠 sandbox/approval（零依赖）；never 红线任何档位都生效
- **webServer route**：`GET/POST /api/dsh-permission-guard/policy`（loopback Host/Origin 校验，参照 hub host-guard）
- GUIDANCE / README 同步

- tsc + client build 绿；verify-release **ALL PASS**（含全新环境装配冒烟）

## 注意事项
- 装后生效链路：用户用官方权限菜单选 Full Access（或设置卡/左下角 chip 切档位）→ 插件 guard 下次工具调用即按新档位决策（配置 mtime 自动检测，无需重启）
- 存量 `~/.dsh/permission-guard.json` 无 `policy` 字段 → 默认 `follow`（不需要手动加）
