# 仓库结构与双推纪律（2026-09-24）

> 背景：MG（MarecGents）基本停止开发，本项目转为本方自持。开发主线迁移至
> `dustinmoon78/deepseek-harness-hub`，MG 仓降级为镜像仓。**核心要求：两个远端进度永远一致。**

## 一、远端结构

| remote | fetch | push | 用途 |
|---|---|---|---|
| `origin` | `dustinmoon78/deepseek-harness-hub` | 新仓 **+** `MarecGents/deepseek-harness-hub`（双 push url） | 日常开发线（`dev-v3` 等） |
| `own` | `dustinmoon78/deepseek-harness-hub` | 同 fetch | 只属新仓的操作（`main`、tags） |
| `fork` | `dustinmoon78/marec-dsh-desktop` | 同 | 历史 fork（旧仓名），勿再使用 |

## 二、日常纪律

1. **开发分支只有 `dev-v3`**；日常发布 = `git push origin dev-v3`，一条命令双远端同落
   （同一批提交 → commit hash 两边天然一致，不存在同步脚本与漂移）。
2. push 输出**必须出现两段结果**（新仓一段 + MG 仓一段）；只看到一段 = 少推一边，当场补推。
3. `main` 与 tags **只属于新仓**：`git push own main` / `git push own --tags`。
   MG 侧 `main` 是保护分支，由常驻 PR（当前 #60：`dev-v3`→`main`）统一收口，不直推。
4. 分支删除同样走 `git push origin --delete <branch>`（自动双删，保持对称）。
