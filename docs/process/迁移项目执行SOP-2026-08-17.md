### 2.8 异常处理
- **插件 crate 版本/API 不匹配**（cargo build 报错）→ 以 `cargo build` / `tauri dev` ACL 报错为准修正版本，同时登记进 PC-4 插件核实清单。
- **@tauri-apps/cli 与 tauri 2.11 不匹配** → 对齐 Cargo.toml 锁定的 tauri 版本后重装。
- **cargo 工具链缺失** → 安装 rustup stable 工具链后重试。
- **EBUSY（Windows 文件被占用）** → 退出占用进程（桌面壳/编辑器）后重试。
- **ACL 报错（capabilities 权限不足）** → 按「真实调用点 → 加对应权限」逐项最小化放行，禁止回退到 `core:default` 全家桶。
- **`cargo tauri dev` 窗口未弹出 / 白屏 / 启动即崩（panic 或非 0 退出）** → 查 `$DSH_HOME/dsh-hub/logs/` + stderr panic 行 → 核对 tauri.conf.json / capabilities → 登记缺陷（X1 排障路径）。

### 5.8 异常处理
- **dsh web 无现成就绪输出**（README/URL 行形态待验证）→ 兜底轮询 `http://127.0.0.1:N` 可连 + 响应可识别（**升格为强制前置步骤**：60s 超时、500ms 间隔、连续 15 次失败即报错——登记缺陷 + 提示日志；防第三方插件伪造 READY 行导航到恶意源）。
- **stdout 出现形似 `READY{}`/`exit{}` 的插件日志行** → 帧前缀 + schema 严格校验丢弃非帧行；exit 判定以 `Child::try_wait` 为准。
- **EBUSY（junction 被占用）** → 退出占用进程后重跑 assemble-profile.mjs。
- **dev 下 `__TAURI_INTERNALS__` 注入导致远程页误判本地窗口** → dev 坚持 `WebviewUrl::External` + 主桥（N13），不启用应用 origin 注入。
- **桥 token 泄露风险**（日志/URL）→ X1 脱敏 + 禁 URL query + 壳重启轮换。
- **sidecar 未收到 token / token 校验失败**（stdio `init{token}` 未达或 env 未注入）→ 拒绝请求 + X1 日志脱敏记录 + 壳侧可见错误（阻断启动或降级为提示，按 X4-④ 语义）。
- **回退线验证失败**（Tauri 壳未就绪）→ 快捷方式/启动命令切回 npm launcher（rc.14），修通后再进 M4 验收。

### 6.8 异常处理

- **EBUSY 覆盖安装** → 升级脚本先杀 sidecar/主进程（T5.1 升级路径）。
- **旧 npm 包 postuninstall 误删安装器快捷方式** → 按 OPS-H2 决策（改名 `DeepSeek Harness (Tauri).lnk` 或文档化「先卸旧包再装安装器」顺序）。
- **Win10 无 WebView2 Runtime 自动安装失败**（离线 / 杀软拦截 embedBootstrapper）→ 重试 N 次 → 提示手动安装 Runtime（附官方下载链接）→ 该端冒烟 FAIL 登记。
- **P4/P9 门禁 FAIL** → 修复后重跑，禁止跳过（铁律 6）。
