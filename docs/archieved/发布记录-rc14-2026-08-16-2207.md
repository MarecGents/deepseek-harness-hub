# 发布记录 rc.14 — 2026-08-16 22:07

> 版本：`0.0.1-rc.14`（WebView2 壳修复版）· 分支：dev-v1 → main（PR #9）→ 三分支同步
> 类型：**阻断性 bug 修复**（全新环境首启崩溃）

## 1. 背景

rc.13 发布后在**测试电脑（全新环境）**暴露阻断 bug：`npm i -g @marecgents/dsh-hub` 安装 rc.13 后，点桌面快捷方式弹「dsh-hub 连续异常退出」，`dsh.log` 显示 `ERR_MODULE_NOT_FOUND: Cannot find package '@marecgents/dsh-hub'`，崩溃 3 次后放弃。本机开发环境从未复现（profile 为 `npm link` scoped 装配）。

## 2. 根因

`bin/launcher.mjs` 的 `ensureBundleInstalled` 在 profile 未注册 scoped 名时走 **bare-name 兜底**装配：

- junction 建在 `profiles/web/node_modules/dsh-hub`（bare）
- bundles 追加 `dsh-hub`（bare）

但 `cordis.patch.yml` 的 loader entry 是 **scoped 名** `@marecgents/dsh-hub`（身份四重相等铁律）→ dsh 装配插件树时从 profile 根 resolve `@marecgents/dsh-hub` → `node_modules/@marecgents/dsh-hub` 不存在 → 启动即崩。

**全新环境必现**：postinstall 只装 dsh/pnpm/建桌面快捷方式，不注册 bundle；首启由 launcher 装配，恰好命中 bare 兜底路径。

## 3. 修复（提交 `f21b246`，PR #9 → main）

`bin/launcher.mjs`：

1. **统一 scoped 装配**：junction 建 `node_modules/@marecgents/dsh-hub`，bundles 只注册 `@marecgents/dsh-hub`（bare 名永不再写入）。
2. **每次启动自愈**：无论 manifest 是否已注册，都校验 scoped junction 存在且指向当前包根；缺失/指错 → 补建/重指（覆盖链接丢失场景）。
3. **幂等清理 bare 遗留**：发现旧 bare junction 或 bundles 里的 bare 名 → 移除（防 duplicate loader entry 双挂）。
4. **新增诊断模式**：`DSH_HUB_ASSEMBLE_ONLY=1` → 只装配不启动（跳过单实例/多实例门禁），用于测试与支持排查。

同步补录 `docs/关键踩坑记录.md` #33（现象 → 原因 → 正确做法 + 升级冒烟项）。
