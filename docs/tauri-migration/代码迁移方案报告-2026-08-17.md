## 1. 概述

### 1.1 目标架构（三层）

| 层 | 形态 | 职责 |
|---|---|---|
| **Tauri Rust 壳**（主进程 `dsh-hub.exe`） | 重写（`src-tauri/` 新增） | 窗口/托盘/主题/单实例/深链/updater/sidecar 托管与崩溃重启 |
| **Node sidecar**（`dsh web --port 0` 随机端口子进程） | 保留 Node 逻辑 | dsh host + 插件层：client 伺服、5 条 HTTP 路由、Cordis 装配、config/workspace/pins/backgrounds API |
| **webview** | 复用前端 | 加载 `http://127.0.0.1:<port>`，运行 dsh web UI + client half（React），**零改动** |

与 spacedrive「Rust core daemon + Tauri 2 壳 + React 前端」（REFERENCE 条目 9）及 surrealist「WebView 壳 + 本地服务」（REFERENCE 条目 10）同构；对应技术路线「Node 运行时以 sidecar 承载」（依据：可行性 §3.1、REFERENCE 9/10）。

### 1.2 迁移原则（与落地报告 §1.1 对齐）

1. **每阶段可运行/可回退**：Rust 全部集中 `src-tauri/`，里程碑独立提交，`dev-v1` 冻结兜底（落地 §1.1-1/2）。
2. **与 rc.14 行为对齐**：每个行为一行「rc.14 → Tauri 目标 → 验收」（落地 §9 验收总表）；行为变更（单实例二次启动聚焦、端口预选）显式列为决策点。
3. **插件层零改动**：client half + config/workspace/pins/backgrounds API + `cordis.patch.yml` 不动（根 AGENTS.md §1 隔离边界）。
4. **不碰 dsh 底层源码**：sidecar 拉官方 `dsh web` CLI（根 AGENTS.md 铁律 1）。
5. **红线不削弱**：启动门控 `DSH_HUB_LAUNCHED=1`、多实例默认拒共存、插件身份四重相等（铁律 2/3/4）。

### 1.3 与两份报告的关系

- 可行性报告 = 为什么：21 项能力映射覆盖度、插件层保留路径、Windows 渲染引擎同源（WebView2）、前置条件 P1–P8。

## 2. 目标架构蓝图

### 2.1 进程模型与通信

```
┌────────────────────────────────────────────────────────────┐
│ Tauri 主进程（Rust，dsh-hub.exe）                            │
│  window.rs / tray.rs / theme.rs / single-instance.rs        │
│  node.rs（sidecar 托管+重启）/ commands.rs / updater.rs      │
│      │ std::process::Command spawn（DSH_HUB_LAUNCHED=1）    │
│      │ stderr 管道逐行 emit "dsh:output"                     │
│      ▼                                                      │
│ Node sidecar（dsh web --port 0，随机端口）                    │
│  dsh host + 插件层：5 条 HTTP 路由 + Cordis 装配 + API 四件套  │
│      │ 伺服 http://127.0.0.1:N                              │
│      ▼                                                      │
│ Webview（WebviewUrl::External）—— dsh web UI + client half  │
└────────────────────────────────────────────────────────────┘
```

通信三通道（审查轮 1 修订 H1/OPS-M1 + 审查轮 2 修订 N1/N2/N3/N16：主桥唯一收敛，依据：可行性 §3.4、REFERENCE 10⑥）：

1. **页面 ↔ sidecar：HTTP/SSE/WS（主桥）**——**服务端由 Node sidecar 的 dsh webserver 伺服（审查轮 2 修订 N1）**：桥端点 `/api/dsh-hub/bridge` 的注册、SSE/WebSocket 升级、mg:* 消息路由与 token 校验/分发全部在 sidecar 侧实现（与现有 5 条插件自有路由同层扩展，`ctx.webServer.register`/`registerUpgrade`，允许改 `src/index.ts` 或新增 host 模块，对应 §3.1 的「index.ts 全原样」放宽为「插件层 API 原样 + 桥端点同层扩展」）；**下行（sidecar/壳 → 页面）= shell-command + 主题请求（壳→页主题请求若有）**，经 SSE/WebSocket 推送；**上行（页面 → sidecar/壳）= workspace-path/session-focus/theme**，同源 `fetch` POST（审查轮 2 修订 N16：workspace-path 回执只列上行，下行不再重复）；远程 dsh 页天然可用，无 IPC 权限依赖，client half 零改动的主通道；
2. **sidecar ↔ 壳：子进程 stdio JSON-RPC（方向标签审查轮 2 修订 N2）**——**stdout 侧（sidecar → 壳）上行**：请求行 `notify`/`applyTheme`/`applySize`（页面经主桥上送或 session/notify 事件触发）+ 事件行 `dsh:output`/`READY{port}`/`exit{code,quitMarker}`；**stdin 侧（壳 → sidecar）下行命令**：仅 `quit`（及未来壳驱动动作）；`dsh:output` 由壳经**主桥 SSE/WS 下行**推送页面（远程页可收，不依赖 Tauri IPC emit，审查轮 2 修订 N3）；窗口级命令不经页面（落地 T4.1 stdio 协议，审查轮 1 补缺 H3）；
3. **壳内本地窗口 ↔ 壳：Tauri IPC（invoke/event）**——仅壳自身页面（splash、M1–M3 临时页、未来壳内设置页）的壳级本地命令（窗口控制/托盘事件/theme-sync），需 `__TAURI_INTERNALS__` + capabilities 授权；**远程 dsh 页不依赖它**。

> 桥接选型（审查轮 1 修订，三报告统一）：**主桥 = HTTP/SSE/WS（方案 B）**——dsh host 远程页天然可用、无 IPC 权限依赖；Tauri IPC（invoke/event）仅用于**壳级本地命令**，需 `__TAURI_INTERNALS__` + capabilities 授权；`dangerousRemoteDomainIpcAccess` 仅方案 A（远程页直接 invoke 窗口级 IPC）需要、主桥不依赖（默认不启用）；**主桥服务端归属（审查轮 2 修订 N1）**：注册/SSE/WS 升级/路由/token 分发全部在 sidecar webserver 侧，Rust 壳不实现 HTTP 桥（落地 T4.9）；`__TAURI_INTERNALS__` 探测仅用于「本地窗口 vs 远程页」判断（通道选择 IPC vs 桥），远程页不依赖它（消除「探测恒真但桥不通」死结，A2/D2）；**接线信号改 env（审查轮 2 修订 N5/R4）**：`DSH_HUB_SHELL=tauri|webviewjs` 由 Rust spawn 时注入（npm launcher 设 `webviewjs`），index.ts 直接读 env 无往返无竞态；壳内本地窗口 IPC 命令集以落地 T4.8（set_window_theme / set_window_size / get_workspace_path）为准（审查轮 2 修订 N11：删除 `invoke("bridge_message")` 表述）；`src/bridge/tauri.ts` 主实现为 HTTP/SSE/WS 客户端 + 薄 IPC 适配。

## 4. 能力实现方案（每项含参考源码位置）

**1. 窗口（WebviewWindowBuilder + 像素单位三态）** [已核实 API 出处]

### 5.2 mg:* 消息协议与页面全局（保持稳定，client half 零改动前提）

- **adapter 探测（审查轮 1 修订 A2/D2 + 审查轮 2 修订 N5/R4）**：主桥为 HTTP/SSE/WS 后，**远程 dsh 页不依赖 Tauri IPC**。**两级判据**：`"__TAURI_INTERNALS__" in window` 探测仅用于判断「本地窗口 vs 远程页」（通道选择：本地页走 IPC，远程页走 HTTP 桥——消除「探测恒真但桥不通」死结，A2）；壳侧 `initialization_script` 注入的自有探针 `window.__DSH_SHELL__ = { type: 'tauri', bridge: 'http' }` 只判「Tauri 壳环境」，**仅作客户端 adapter 提示，不充当本地窗口判据、不被 index.ts 信任**（普通 window 全局可被页面/插件覆写，非完整性边界）。**sidecar 接线信号改走 env（R4）**：Rust spawn 时注入 `DSH_HUB_SHELL=tauri`（npm launcher 设 `webviewjs`），`index.ts` 直接读 env——**不再依赖 Node 读页面 window（evaluateScript 往返/时序竞态均消除）**；`index.ts` 接线点条件分支：`launchedByShortcut()` 且 env `DSH_HUB_SHELL=tauri` → tauri-shell，否则 → 现 desktop.ts（**回退线**，落地 T4.6）。**页面就绪握手（N5）**：页面加载后经主桥向 sidecar 上报 adapter 类型/通道（`__mgShellReady` 契约扩展为「adapter 类型 + 通道 + 探针结果」），sidecar 结合 env 与握手结果决定接线分支；握手遵循「先验证再导航」（READY 端口交叉验证，落地 T4.4）。
- **回退开关语义（审查轮 1 修订 D2）**：`DSH_HUB_SHELL=webviewjs` **未定义读取方的问题已闭合**——Rust 壳读到该 env 时仅做提示/退出（Tauri 壳自身无法承载 webviewjs 壳）；真正的回退 = **快捷方式/启动命令切换回 npm launcher**（dev-v1 冻结存档），回退全链路冒烟（含数据双向兼容）入 verify-tauri-release（落地 T5.5）。
- `DesktopShellHandle` 接口（applyTheme/applySize/dispatchEvent/getCurrentWorkspacePath/playSound/notifyTaskComplete/dispose，desktop.ts L67-116）**保留**，Tauri 实现替换：applyTheme/applySize/notifyTaskComplete 经 sidecar↔壳 stdio JSON-RPC **上行**（sidecar→壳 stdout 请求行，审查轮 2 修订 N2 方向标签），dispatchEvent 经主桥 SSE/WS 下行（落地 M4 里程碑 T4.6）。
