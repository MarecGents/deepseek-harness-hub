# 第四轮改进（原生托盘菜单 / 主题外壳化 / 通知快捷方式 / 全局 dsh 测试）— DMAIC

## Define（定义）— 4 项 CTQ 与用户决策

| # | CTQ | 用户决策 |
|---|---|---|
| 1 | 托盘菜单 | **回退原生菜单**（系统渲染、鼠标位置；放弃自绘 HTML）。4 项：显示/隐藏主界面（label 动态）、打开工作区、**新建会话**（原"新建任务"）、退出。左键单/双=显示窗口。显示/隐藏语义：窗口可见未最小化=「隐藏主界面」（点击隐藏到托盘）；否则（含任务栏最小化/最小化到托盘/关闭到托盘）=「显示主界面」 |
| 2 | 主题设置 | **只控外壳 chrome**：深色=黑色标题栏、浅色=白色标题栏（默认白/黑）；跟随 dsh=外壳跟随 dsh 深浅色（皮肤 token）。不动 dsh 页面 |
| 3 | 会话完成通知 | 命令链路已通（实测日志 toast sent）但 Windows 不显示 → **开始菜单快捷方式 + AUMID**（最可靠未打包 toast 方式）+ 保留注册表双保险 |
| 4 | 测试用全局 dsh | 用真实 `~/.dsh`（模型配置都在）；**关闭 3080 旧实例**；删除隔离 temp 目录；**创建桌面+开始菜单快捷方式**（用户自行关闭/手动打开测试） |

## Measure / Analyze（测量与分析）— 取证

1. **自定义菜单反直觉（用户反馈）**：右键弹出窗口 + 菜单出现在窗口右下角。自绘 HTML 菜单受"只能在窗口内渲染"约束，本质无法做到原生菜单的"鼠标位置"体验 → 回退原生（放弃样式自定义，Q1 用户明确接受）。
2. **主题命令已触发但不可见（实测日志 03:29:51-56）**：set_window_theme light/dark/system 全部到达；frameless 窗口 DWM 不可见、标题栏走皮肤 token → 无视觉变化。修：外壳主题 = `body[data-mg-shell-theme]` 属性 → 标题栏黑/白覆盖 CSS。
3. **通知命令已触发但不显示（实测日志 03:27:31）**：`notify: toast sent` 成功但用户未见 toast。AUMID 注册表键在（实测确认 DisplayName/IconUri 落盘）→ 追加**开始菜单快捷方式 + AUMID 属性**（微软文档未打包应用可靠方式；`HKCU\Software\Classes\AppUserModelId` 注册表法在某些构建不生效）。
4. **open-workspace 链路（E2E round 7 实证）**：`client-ready=true` + `open_workspace_path invoked from page: <dsh home>` —— 原生菜单 eval 派发 → client handleShellCommand → invoke → Rust 兜底 $DSH_HOME 全通。round 6 未触发系客户端未挂载/并发干扰，round 7 修复验证。
5. **toggle 语义修正**：点击托盘会夺走窗口焦点 → 用 `is_focused` 判断会误「显示」。改为 `is_visible && !is_minimized`（可见未最小化=可直视内容）。
