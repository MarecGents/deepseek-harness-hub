## 1. 概述

### 1.1 目标

将 dsh-hub（`@marecgents/dsh-hub`，DeepSeek Harness 桌面端框架）的**桌面壳层**从「Node + @webviewjs/webview 0.4.2 + koffi FFI 的 WebView2 壳（Windows 专属）」整体迁移到 **Tauri 2.x（Rust 壳，Windows / macOS / Linux 三端）**，实现三端支持、壳二进制 ~10MB 级、无边框 + 透明窗口 + 背景图穿透视觉体系延续（目标与不变式见 `docs/dsh桌面端技术路线-2026-08-16.md` §2、§3，下文简称「技术路线」）。

### 1.2 范围

| 层 | 处置 | 依据 |
|---|---|---|
| **壳层**（`src/desktop.ts` + Windows 专属 `services/` + `bin/*` 启动器） | **整体重写为 Rust** | `src/AGENTS.md`（desktop.ts 标注「Tauri 迁移时整体重写」）；`src/services/AGENTS.md`（dwm-theme / tray / explorer / screen 标注「重写」）；`bin/AGENTS.md`（launcher 语义保留、实现替换）；技术路线 §3 |
| **桥接层**（webviewjs IPC 协议 ↔ 页面） | **重写**（webviewjs 回调模型 → 主桥 HTTP/SSE/WS + 壳级本地命令 Tauri IPC + sidecar↔壳 stdio JSON-RPC，见 §3.4；审查轮 1 修订 H1） | 技术路线 §3；`src/services/AGENTS.md`（theme-sync 标注「保留（桥）」） |
| **插件层**（React client UI + config/workspace API + Cordis 插件装配 + profile/patch 机制） | **原样保留，目标零改动** | AGENTS.md §1 隔离边界；技术路线 §3「插件层零改动」；§5.1 分支策略（dev-v2 迁移、dev-v1 冻结） |

### 1.3 判断结论摘要

1. **技术可行性：高**。逐项能力映射（§2 表）显示：窗口管理、托盘、单实例、深链、自动更新、本地 HTTP 服务、配置持久化等均由 Tauri 2 核心 API（`crates/tauri/src/`，本地源码已核实）或官方插件（surrealist/spacedrive 的 Cargo.toml 实证，REFERENCE 条目 9/10）覆盖；需自研的只有「多实例检测」「崩溃重启监督」「托盘→页面命令桥」三块逻辑移植，工作量可控。
2. **插件层保留：高可行性**。client half 是纯浏览器产物（tsdown CJS bundle，经 dsh client-modules 伺服），Tauri webview 加载同一 `http://127.0.0.1:<port>` 即可零改动运行；config/workspace/pins/backgrounds API 与 Cordis 装配机制都在 **Node sidecar** 内原样保留（依据 REFERENCE 条目 2/6/7、`package.json` dsh.client.inject、`tsdown.config.ts`）。
3. **渲染一致性（Windows）：已核实一致**。Tauri 在 Windows 上经 WRY 使用 WebView2（REFERENCE 条目 11），与现壳渲染引擎同源 → `docs/关键踩坑记录.md` #32 的 fixed 合成结论（body portal 半透明不透出背后、自绘画图是唯一可靠路径）在 Windows 上原样成立；macOS/Linux 需逐端像素验证（技术路线 §6 已声明）。
4. **最大不确定项**：Node sidecar 的分发体积（Node ≥24 运行时捆绑使安装包显著大于 ~10MB 壳目标）、Windows 代码签名 / macOS notarization、三端渲染与托盘差异——均为**工程问题而非可行性障碍**，见 §5 风险与 §7 前置条件。

- 「dwm-theme → window-vibrancy / window-effects」：`window-vibrancy` 是**社区 crate**（REFERENCE 条目 3），且现壳**并无**模糊/毛玻璃需求（背景图穿透是页内 CSS，见 #2）；核心需求是 `set_theme` / `set_title_bar_style` / `ThemeChanged`，vibrancy 仅当未来要亚克力效果时再评估。
- 「theme-sync → tauri-plugin-window-state + Theme 事件」：`window-state` 只负责**窗口几何持久化**；主题同步的正确对应是 `Window::set_theme` + `WindowEvent::ThemeChanged` + 页内桥（#5），两件事应分开映射。

## 3. 保留层可行性：插件层在 Tauri 时代的承载方式

### 3.1 总体结论

插件层**原样保留、零改动**是可行的，且是唯一符合 AGENTS.md 铁律 1（绝不修改 dsh 底层源码）的路径：整个 Cordis 插件树（含 dsh-hub host half 的 config/workspace API）继续运行在 **Node sidecar**（Tauri 壳 spawn 的 `dsh web --port 0` 进程）内；Tauri 壳只做窗口/托盘/系统能力，通过桥接层与 sidecar 通信。此架构与 spacedrive「Rust core 守护进程 + Tauri 2 壳 + React 前端」的 daemon-client 范式同构（REFERENCE 条目 9），也对应技术路线 §3 的「Node 运行时以 sidecar 承载」。

### 3.2 client half：零改动（已核实）

- 构建形态：`tsdown.config.ts` 产出 CJS 浏览器 bundle（`window.__ModuleLoader__.load({ id: '@marecgents/dsh-hub', … })`，platform 模块 external），由 dsh client-modules 伺服为 `/plugins/dsh-hub/client.js`；`package.json` `dsh.client.inject` 声明装载（`@deepseek-ai/dsh-client-runtime` 等）。
- 运行载体：client 在**浏览器环境**执行（React + `ctx.slots.inject('settings.plugin.item')` + body portal 右侧栏 + skins/backgrounds DOM 注入）。Tauri webview 加载的仍是同一个 `http://127.0.0.1:<port>` 页面 → client 脚本、slot 注入、__DSH_BOOT__ 装载、`fetch('/api/dsh-hub/config')` 同源请求全部不变。
- 依据：`src/client/index.ts`（slot 声明 + `__mgShellReady` 桥 + settings card + 右侧栏装配）；REFERENCE 条目 6（`platform: web` 挂载方式对 Tauri 2.x webview 迁移可直接沿用）、条目 7（client slots/多语言/设置卡注入规范、tsdown 冻结模块表）。

### 3.3 host half（API 层）：保留（已核实）

- config/workspace/pins/backgrounds API 是 `ctx.webServer.register(route)` 的插件自有 HTTP 路由（`/api/dsh-hub/*`），注册逻辑在 Node sidecar 内，与壳无关 → **保留不动**（`src/services/config-api.ts` / `workspace-api.ts` / `pins-api.ts` / `backgrounds-api.ts`；services/AGENTS.md 标注全部「保留」）。
- profile/patch 装配：`cordis.patch.yml`（`disabled: !!js process.env.DSH_HUB_LAUNCHED !== '1'` 门控）+ launcher `ensureBundleInstalled`（scoped junction 自愈 + bundles 登记）→ 装配逻辑保留 Node 侧，位置从「launcher 进程」移到「sidecar bootstrap 脚本」（Rust 壳 spawn 前或 dsh 启动前执行一次），语义与 rc.14 的启动自愈完全一致（`bin/launcher.mjs` L107-228；AGENTS.md §5.4/5.5）。
- 会话/agent 事件驱动的「声音 + 通知」逻辑（`src/index.ts` `ctx.on('session/event')`）保留 Node 侧，仅把「调用 shell 播放/通知」改为「经桥调用 Rust 壳」或「Node 侧直播/直发」（#14/#15 建议保留 Node 侧实现）。

### 3.4 桥接层：必须重写，主桥收敛为 HTTP/SSE/WS（审查轮 1 修订 H1/OPS-M1）

现壳桥（`src/desktop.ts` + `src/services/theme-sync.ts` + `src/client/index.ts`）：host ↔ 页面经 webviewjs `window.ipc.postMessage`（`mg:workspace-path:` / `mg:session-focus:` / `mg-theme:`）+ host `evaluateScript` 注入（`__mgSendCurrentWorkspace`、`__mgShellReady` 探针、`dispatchEvent('mg:shell-command')`）。Tauri 下替换为**三层通道**，其中主桥唯一、其余两条为配套：

- **主桥（页面 ↔ sidecar）= HTTP/SSE/WS（方案 B，唯一主桥）**。**服务端归属（审查轮 2 修订 N1，收敛）**：桥端点 `/api/dsh-hub/bridge` 的**注册、SSE/WebSocket 升级、mg:* 消息路由与 token 校验/分发全部由 Node sidecar 的 dsh webserver 伺服**——与现有 5 条插件自有路由（`/api/dsh-hub/{config, workspace/list, workspace/git, pins, backgrounds/*}`）同层扩展（`ctx.webServer.register`/`registerUpgrade`，REFERENCE 条目 2），实现位置允许改 `src/index.ts` 或新增 host 模块（对应迁移 §3.1 的「index.ts 全原样」放宽为「插件层 API 原样 + 桥端点同层扩展」）；**Rust 壳不实现 HTTP 桥**，仅保留壳级 IPC 命令白名单校验。下行（sidecar/壳 → 页面）：托盘命令 `mg:shell-command`、主题请求（壳→页主题请求若有），经 SSE/WebSocket 推送，页面用 `EventSource`/`WebSocket` 订阅；上行（页面 → sidecar/壳）：workspace-path 回执、session-focus、主题上报，用同源 `fetch` POST（审查轮 2 修订 N16：workspace-path 回执只列上行，下行不再重复）。桥鉴权（Host 白名单/Origin 校验/会话级 token）**在 sidecar 端点侧实现**（X4-④，参考 better-sidebar 的 Host 头信任围栏做法 [REFERENCE 条目 6]，但 dsh-hub 自有层自建、不得引用其围栏带过）；token 由 Rust 壳 spawn sidecar 时生成、经 stdio/env 下发，页面经初始化脚本注入 `window.__DSH_BRIDGE_TOKEN__` 获取（禁止放 URL query，日志脱敏），详见 §5.6/落地 X4-④。桥语义（`mg:*` 消息 + `__mgShellReady` 重试契约）原样保留，只换传输层。**优点**：dsh host 远程页（`http://127.0.0.1:<port>`）天然可用、不依赖 Tauri IPC 权限注入（无需 `dangerousRemoteDomainIpcAccess`）、client half 可脱离 Tauri 在普通浏览器调试、与 dsh webserver 生态（REFERENCE 条目 2 的 register/registerUpgrade）天然契合；REFERENCE 条目 6 的 better-sidebar `/sidebar/ws/terminal` WebSocket 路由即为同构先例。
- **sidecar ↔ 壳 = 子进程 stdio JSON-RPC（方向标签审查轮 2 修订 N2，以壳「父进程」视角定义）**。**stdout 侧（sidecar → 壳）上行**：请求行 `notify{title,body}` / `applyTheme{dark}` / `applySize{w,h}`（页面经主桥上送或 session/notify 事件触发，由 sidecar 转发给壳改窗口/弹 toast）+ 事件行 `READY{port}` / `output{line}` / `exit{code,quitMarker}`；**stdin 侧（壳 → sidecar）下行命令**：仅 `quit`（及未来壳驱动动作）。**`dsh:output` 日志回灌不依赖 Tauri IPC emit（审查轮 2 修订 N3）**：sidecar stderr/stdout 逐行经主桥 SSE/WS 下行推送（远程页可收）；本地窗口壳级事件才走 IPC。`notifyTaskComplete` 跨进程路径由此闭环：sidecar 内 session/event → stdio stdout 上行 `notify` → `notify.rs` 弹 toast（落地 T4.1 stdio 协议任务）。
- **Tauri IPC（invoke/event）= 壳级本地命令通道，仅本地窗口内可用**。用于壳自身页面（splash、M1–M3 临时页、未来壳内设置页）的窗口控制/托盘事件/theme-sync；需要 `__TAURI_INTERNALS__` + capabilities 授权。**远程 dsh 页不依赖它**：`dangerousRemoteDomainIpcAccess`（`RemoteDomainAccessScope`，见 `tauri-utils/src/config.rs` / `config_v1/mod.rs` L1236/L1302）**仅方案 A（远程页直接 invoke 窗口级 IPC）才需要，主桥默认不启用**；配置时白名单收窄到 IP `127.0.0.1`（端口随机故按 IP 授权）。**探测判据两级化 + env 信号握手（审查轮 2 修订 N5/R4）**：`__TAURI_INTERNALS__` 探测仅用于判断「本地窗口 vs 远程页」（通道选择 IPC vs 桥）；壳侧注入的自有探针 `window.__DSH_SHELL__` 仅判「Tauri 壳环境」、只作客户端 adapter 提示（页面可覆写，非完整性边界）；**sidecar 接线信号改走 env**——Rust spawn 时注入 `DSH_HUB_SHELL=tauri`（npm launcher 设 `webviewjs`），index.ts 直接读 env 无往返无竞态；页面就绪后经主桥握手上报 adapter 类型/通道，sidecar 据此决定 tauri-shell 分支（见迁移 §5.2、落地 T4.6）。

### 3.5 需要 Rust 重写的部分（清单）

仅：窗口生命周期与几何（desktop.ts createWindow 全部）、托盘（tray.ts 全部）、单实例/多实例/崩溃重启（bin/launcher.mjs + lock.mjs + multi-instance.mjs）、主题同步的「壳端」（theme-sync 的 IPC 侧 + dwm-theme）、屏幕探测（screen.ts）、explorer 前置激活（explorer.ts 的激活部分）、通知/声音的壳端调用（若 Rust 化）、深链与自动更新（新增）。合计约 6 个 TS 模块 + 5 个 bin 脚本，均已在 §2 表逐项给出对应。

## 4. 渲染一致性（Windows 已核实一致，三端需验证）

### 4.1 引擎同源（已核实）

- 现壳：`@webviewjs/webview@0.4.2`（`package.json` dependencies）在 Windows 上即 WebView2 渲染。
- Tauri 2：`tauri-runtime-wry` 对接 **WRY**，WRY 在 Windows 上调 **WebView2**（REFERENCE 条目 11；ARCHITECTURE.md「WRY determines which webview is used」）。本地 Tauri 源码仓库 Cargo.lock 锁定 `tauri 2.11.5 / tao 0.36.0 / wry 0.56.0`（REFERENCE 条目 11 提醒）。
- 结论：**Windows 上渲染引擎同为 WebView2（Chromium）**，页内 CSS 行为、字体渲染、合成器行为与现壳一致。

### 4.2 关键踩坑 #32 的 fixed 合成结论（Windows 上原样成立，已核实）

`docs/关键踩坑记录.md` #32（L163-171）的三条结论均为 **Chromium 合成器行为**，与壳实现无关：

- 教训 5（L170）：body portal 的 fixed 面板，半透明背景（color-mix / opacity / backdrop-filter）**不透出背后内容** → 自研右侧栏只能把背景图画在面板自身上（多层背景 + `background-attachment: fixed`）。
- 教训 6（L171）：`position:fixed` 本身触发合成层、半透明背景不采样背后，与挂载点（body 还是 `#root`）无关；唯一能透出的是非定位流内元素；「注册进官方树获得透出」方案永久不可行。
- 正确做法（L168）：背景图注入应用 frame 层（`#root div[style*="grid-template-columns"]` 结构契约锚点 + 双层背景 + 蒙层）+ 左/中/右三栏内容根单层 75% 半透明（`[data-slot="sidebar"/"conversation"/"details"] > div` 官方 slot 契约锚点）。

这些锚点与合成结论在 Windows Tauri（同一 Chromium 内核）下**行为不变**：背景图、皮肤（`--dsw-*` token 覆盖，`src/client/skins.ts`）、右侧栏自绘画图方案、置顶会话的 stable 锚点（`data-slot`/role）均可原样延续。**待验证项**：macOS WKWebView / Linux WebKitGTK 上 fixed 合成、`color-mix`、`background-attachment: fixed` 行为可能不同（技术路线 §6 已声明「M1/M2 逐端做透明背景像素验证」），须在 M1/M2 里程碑做像素级回归（验证项：frame 层背景透出 ~25%、右栏 25% 透出、皮肤 token 覆盖率）。

## 5. 风险分析

### 5.1 Node sidecar 承载：体积 / 分发 / 崩溃

- **体积（高风险，修正技术路线 §2 的 ~10MB 目标）**：dsh 运行时要求 `Node ^22.19 || >=24`（REFERENCE 条目 2；`package.json` engines `node >=24.0.0`），dsh-hub 插件层必须整树 Node 运行 → 三端安装包必须**捆绑 Node 运行时**（技术路线 §6 已承认「按平台下载固定 Node 版本」）。Node 24 运行时压缩后约 25-40MB/平台，叠加 node_modules 与 Tauri 壳后，**安装包实测预计 40-80MB 级**（待验证，无本地实测数据）。「~10MB」只能指 Rust 壳二进制本身；报告须向用户如实修正。Node SEA/单文件化与 dsh 的动态插件装配（profile bundles 动态 import、junction、`cordis:` 前缀隔离）冲突（REFERENCE 条目 2/4 的 loader 机制），不可行（待验证 SEA 约束）。
- **分发**：`externalBin`（spacedrive 打包 sd-daemon 的先例，REFERENCE 条目 9）可把 Node 运行时作为 sidecar 打进安装包；`tauri-plugin-shell` 的 sidecar 运行（surrealist `std::process::Command` spawn 范式，REFERENCE 条目 10）。sidecar 与壳的版本配对、`DSH_HOME` 环境继承、工作目录约定需在 M4 验证。**供应链校验（审查轮 1 补缺 A3）**：下载固定 Node 版本必须「官方源固定 + SHASUMS256 校验 + 失败即中止」；`externalBin` 打包时对 node 二进制做哈希登记；「首启联网按需下载运行时」路径**默认关闭、仅显式 opt-in**（避免下载物被替换 = 任意代码执行）。
- **崩溃**：sidecar 意外退出由 Rust 壳监督重启（≤3 次 + 1200ms 延迟，语义同 `bin/launcher.mjs` L29-32/L376-407）；`quit.marker` 判别主动退出保留（AGENTS.md 铁律 3）。现壳 webviewjs teardown 0xC0000005 崩溃（`src/desktop.ts` L462-468、`src/index.ts` L130-139 注释）在 Rust 壳下**架构性消失**（不再有 webviewjs 原生 teardown），重启逻辑可简化。

### 5.2 安装体验变化（npm 全局包 → 原生安装器）

- 现：`npm i -g @marecgents/dsh-hub --allow-scripts=…` + postinstall 快捷方式 + launcher junction 自愈（AGENTS.md §5.2/5.5/5.6）。
- 迁移后：原生安装器（Windows MSI/NSIS、macOS dmg、Linux AppImage/deb/rpm，tauri-bundler 产物）+ **插件层仍需落入 `$DSH_HOME/profiles/web`**（`@marecgents/dsh-hub` bundle 装配）。需设计**双通道**：① 原生安装器装壳（含 sidecar Node + **内置 dsh-hub 插件包——`bundle.resources` 声明打包 `lib/`+`assets/`+client bundle，审查轮 2 修订 G1，落地 T5.1**）；② 首启时由 Rust 壳/引导脚本执行 profile 装配（复用 `ensureBundleInstalled` 语义，**装配源路径 = 安装器内嵌资源目录，经 `DSH_HUB_PACKAGE_ROOT` env 或相对 sidecar 脚本解析注入，见落地 T4.2**）。可参照 Reasonix 的「npm 仅做原生二进制分发」模式（REFERENCE 条目 5：`npm/reasonix` + optionalDependencies `@reasonix/cli-*`）决定 npm 包是否继续作为分发入口。**平台依赖矩阵（审查轮 1 补缺 A6/OPS-M8）**：Windows WebView2 Runtime（Win11 预装；Win10 需 `bundle.windows.webviewInstallMode: embedBootstrapper`，已核实 spacedrive `tauri.conf.json` L94-99）；Linux WebKitGTK/GTK 系统库缺失与 Wayland/X11 差异；macOS hardened runtime + entitlements——矩阵与逐端冒烟用例见落地 T5.5。**卸载清理边界（审查轮 1 修订 OPS-H3/C3）**：安装器「删除应用数据」指向 `$DSH_HOME` 且**默认不删**（仅用户显式选择），精确清理清单与「默认保留 profiles/sessions」边界见落地 T5.1/§6。**存量 npm rc.14 用户过渡（审查轮 1 修订 OPS-H2）**：先装安装器、保留 `$DSH_HOME`、快捷方式改名或覆盖策略、npm postuninstall 不误删安装器快捷方式/数据，见迁移 §7.5 与落地 P7。

- 迁移期风险：壳/插件接口契约漂移（桥协议需版本化冻结）；双轨发布负担（npm rc 版 WebView2 壳 vs 原生 Tauri 版）；`verify-release.mjs` 门禁需扩展 Tauri 构建链路（AGENTS.md §5.2 铁律：发布前全 PASS）。
- 缓解：先做 M1/M2 最小闭环（§7 P6）验证引擎一致性与桥协议，再进入 M3-M5；插件层在 M4 前**冻结改动**（避免「插件层零改动」验收被漂移破坏）。**回退线退役条件（审查轮 1 修订 M3）**：webviewjs 双壳回退线（desktop.ts + `@webviewjs/webview`/koffi）**首个正式版发布即移除**，维护成本限定 dev-v2 过渡期；设依赖清理门禁（verify-tauri-release 检查 webviewjs/koffi 不在 dependencies）。

### 5.6 其余已识别风险

- **桥与 IPC 安全（审查轮 1 修订 B2/H2 + 审查轮 2 修订 R2/N1）**：主桥（HTTP/SSE/WS）端点 `/api/dsh-hub/bridge` 由 **sidecar（Node host half）伺服并校验**（与 §3.4 主桥归属收敛一致——Rust 壳不在该 HTTP 路径上，实现者不得照旧文在 Rust 侧建校验）——强制 Host 头白名单（`127.0.0.1:<port>`，参考 better-sidebar Host 头信任围栏做法、dsh-hub 自有层自建）+ **Origin 校验（WS/SSE upgrade 与 POST 同强度强制——WebSocket 不受 CORS 约束、Host 头对 IP 直连恒等于白名单值，Origin + token 才是真闸门）** + **会话级 token（R2）**：每次壳启动由 Rust 壳生成 → 经 stdio `init{token}`/env 下发 sidecar → **端点侧校验**；语义为会话级（非单次使用），兼容 SSE 长连接与多次 POST；页面经初始化脚本注入 `window.__DSH_BRIDGE_TOKEN__` 获取（**禁止放 URL query**）；壳重启即轮换；X1 日志明确不打印 token（日志脱敏）。**Rust 侧只保留壳级 IPC 命令白名单校验**（generate_handler 显式注册）。Tauri IPC 仅本地窗口内壳命令使用；`dangerousRemoteDomainIpcAccess` **默认不启用**（仅方案 A 需要；配置时白名单按 IP `127.0.0.1` 授权，端口随机）。
- **渲染一致性回归**：dsh 升级重编译后 `#root div[style*="grid-template-columns"]` / `data-slot` 锚点可能失效（#32 教训 1/3、#29），升级冒烟项需纳入 Tauri 验收（AGENTS.md §3 背景图豁免的升级冒烟要求）。
- **体积预期管理**：~10MB 壳目标与 40-80MB 实际安装包的落差（§5.1）需在路线文档与用户沟通中明确。

## 7. 结论

### 7.1 可行性评级：**高**

- **已核实支撑**：Windows 渲染引擎同源（§4.1）；壳层 21 项能力映射中约 **12 项**由 Tauri 核心 API/官方插件直接覆盖（含 #13「覆盖/保留混合」）、**5 项**逻辑移植、**3 项**保留、**1 项**插件 API 待验证（§2 表，速览与明细一致，审查轮 1 修订 M11）；插件层保留路径与 spacedrive/surrealist 两个生产级 Tauri 2 工程同构（REFERENCE 条目 9/10）。
