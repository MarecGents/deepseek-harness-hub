# dsh-hub 漏洞修复方案（2026-08-16）

> 依据：docs/深度审查报告-2026-08-16-1603.md。每项 = 根因 → 修复方案 → 落地点 → 风险。方案经审查确认后执行。

## A. 已确认必现

### A1 pin 图标裁剪
- 根因：PIN_PATH 是 Material push_pin **24 栅格**路径（坐标 5-19），写代码时误把 viewBox 设为 `0 0 16 16` → 右侧/底部裁剪。
- 方案：`viewBox` 改 `0 0 24 24`（width/height 保持 14）。
- 落点：pin-conversations.ts PIN_FILLED_SVG / PIN_OUTLINE_SVG。
- 风险：无（纯几何修正，三处一致）。

### A2 深色 tooltip 白字浅底（terminal/aurora）
- 根因：这两套深色 `tooltip-bg` 设计为"反色浮层"（#a9f0a9 / #e2dcff），但官方 Tooltip 文字固定白色 → 不可读。当初文档记录了"反色浮层有意为之"，未考虑官方白字。
- 方案：terminal dark `tooltip-bg`/`toast-bg` → `#0e1c10`（=bg-layer-1）；aurora dark → `#151331`（=bg-layer-1）。同步 docs/skins/terminal.md + aurora.md 色板表。
- 落点：skins.ts + docs/skins/*.md。
- 风险：仅深色 tooltip 外观变化（可读性提升）；与"反色浮层"设计意图冲突 → 设计意图更新为"浮层用深色 + 官方白字"。

### A3 dsh-hub 终端命令绕过多实例门控
- 根因：launcher.mjs 有 detectRunningDshInstances + allowMultipleInstances 确认流程；dsh-hub.mjs 只做 PID 锁，缺同一套检测。
- 方案：把多实例检测+确认抽成共享模块 `bin/multi-instance.mjs`（`detectRunningDshInstances(log)` + `enforceSingleInstance(log, alert)` 返回是否放行），launcher.mjs 与 dsh-hub.mjs 共用。
- 落点：新建 bin/multi-instance.mjs；launcher.mjs 改调共享；dsh-hub.mjs 检测到已有实例 → 默认拦截（alert 说明）→ exit；allowMultipleInstances=true → confirm 是/否。
- 风险：dsh-hub 命令行为收紧（符合铁律 #4，属修复）；dsh-hub 在终端运行时 alert/confirm 用 PowerShell MessageBox（已有先例）。

### A4 保存窗口宽高重启不生效
- 根因：effectiveConfig 恒把 width/height 置 undefined（早期注释"总是 3/4 屏"）；hasStoredWindowSize 死代码。
- 方案：effectiveConfig 用 `stored.width/height`（hasStoredWindowSize 判断有值才用，无则 undefined）。
- 落点：index.ts effectiveConfig。
- 风险：保存过尺寸的用户重启按保存值开窗（预期）；未保存过不变。

### A5 搜索空结果置顶区闪现
- 根因：detectSearch 靠"所有行都是 button"；空结果 0 行 → 误判非搜索。
- 方案：inSearch =（行数>0 且全 button）或（行数==0 且 slot 内有可见搜索输入 `input`）。搜索输入存在性用 `slot.querySelector('input')` 且 `offsetParent !== null`（可见）。
- 落点：pin-conversations.ts detectSearch。
- 风险：空列表（非搜索、0 会话）时 slot 无 input → 非搜索 → 置顶区逻辑照旧（live 空 → hidden，无影响）。

### A6 右侧栏 Git 分支名当 commit hash
- 根因：workspace-api gitInfo 把 `head: branch` 返回，客户端 `git.head.slice(0,7)` 截的是分支名。
- 方案：host gitInfo 增加 `branch` 字段、`head` 改为 `rev-parse --short HEAD`；客户端显示优先 `head`（短 hash）。
- 落点：workspace-api.ts + right-sidebar.tsx（显示逻辑不变，数据语义修正）。
- 风险：低（数据语义修正）。

## B. 竞态/逻辑

### B1 dirtyDelta 复活
- 根因：boot 合并 `...dirtyDelta.added` 未过滤 `removed`（先置顶再取消 X → added/removed 都有 X → X 复活）。
- 方案：合并 added 时过滤 `removed`（同 id 在 removed → 跳过）；合并完成后清空 dirtyDelta。
- 落点：pin-conversations.ts boot 合并段。
- 风险：无（一行语义修正，符合设计 v3.1）。

### B2 内容匹配跨文本误标
- 根因：mapRowByContent 只要求"某叶子文本 == 唯一 displayTitle"，未排除状态/时间等元素（如标题"运行中"与状态文案碰撞）。
- 方案：候选叶子过滤：① `getComputedStyle(el).position === 'absolute'` 排除（visuallyHidden 是 absolute）；② 字号 < 13px 排除（时间 12px，标题 14px）；③ 最长匹配校验：行内存在更长叶子文本包含该标题 → 跳过。
- 落点：pin-conversations.ts mapRowByContent。
- 风险：极端渲染结构可能漏配（跳过 = 安全）；升级回归清单加"标题 DOM 结构"项。

### B3 空 ready 快照清空 pins
- 根因：foldReadySnapshot 不判空——连续两次空 byId → 全剪并 persist 落盘。
- 方案：快照 `ids.length === 0`（byId 空）时本轮跳过剪枝（不计数、不删）；至少一次非空快照后才开始 missingStreak 计数。
- 落点：pin-conversations.ts foldReadySnapshot。
- 风险：无（数据保护）。

### B4 多标签置顶数据丢失
- 根因：无 `storage` 监听；boot 后不重拉 pins.json；全量 PUT 最后写者胜。
- 方案：① 加 `window.addEventListener('storage')`：其他标签写 LS → 重读 LS + 重拉 pins API + 合并；② 保持全量 PUT（最后写者胜文档化，storage 覆盖多标签主场景）。多实例（跨端口）storage 不触发 → 保持文档化注记。
- 落点：pin-conversations.ts。
- 风险：低（增量同步，不改写路径语义）。

### B5 同标签连续 PUT 乱序
- 根因：并发 fetch PUT 多连接乱序。
- 方案：写路径串行化——模块级 promise 链 `writeQueue = writeQueue.then(() => apiPutPins(ids)).catch(() => {})`；每次 persist 排入（中间状态自然覆盖为最后值）。
- 落点：pin-conversations.ts persist/apiPutPins。
- 风险：无（串行化，最终一致）。

### B6 mg:shell-command 监听泄漏
- 根因：window.addEventListener 未包 ctx.effect。
- 方案：包进 ctx.effect，disposer removeEventListener。
- 落点：client/index.ts。
- 风险：无（HMR 安全修复）。

### B7 并发保存竞态
- 根因：settings-card 保存响应乱序 `setDraft(saved)` 覆盖新草稿；host 读-改-写丢字段。
- 方案（client）：保存发起时记录"请求序号"，响应到达时若 draft 自发起后已变化（保存基线比对）→ 只更新 config，draft 保留用户编辑；否则照旧更新 draft。onPickSkin 同处理。
- 落点：settings-card.tsx。
- 风险：保存后草稿状态需保留"未保存"提示（dirty 仍 true）——符合预期（新编辑未保存）。

### B8 boot 皮肤恢复竞态
- 根因：fetchStoredSkin().then(applySkin) 无条件应用，可能晚于用户手动切皮肤。
- 方案：模块级 `userPickedSkin` 标志（onPickSkin 置位）；boot 应用前检查标志 → 已操作则跳过。
- 落点：client/index.ts + settings-card.tsx。
- 风险：无。

## C. 进程/身份

### C1 hub-exe 缓存自指 + 每启重建
- 根因：cacheKey 用 `process.execPath` 的 stat——guard 运行时代 execPath=guard 副本（rcedit 改过 mtime/size）→ key 与首次（真 node）不等 → 每启重建；且重建时 rmSync 运行中的 guard → EBUSY → 直启路径静默回退。
- 方案：① cacheKey 改 `${process.versions.node}|${VERSION}`（node 升级 = 版本号变，足够触发重建；rcedit 不改 node 版本号）；② main() 流程改：先 `await ensureHubBinaries()`（此时运行的是真 node，guard 无进程占用，重建安全）→ 再 `relaunchAsGuard()`（re-exec 到新 guard）。
- 落点：hub-exe.mjs cacheKey/ensureHubBinaries；launcher.mjs main 顺序（async）。
- 风险：第一次启动多一次校验（幂等，key 匹配即跳过）；node 升级后旧 guard 文件被安全重建。

### C2 guard spawn 失败静默退出
- 根因：relaunchAsGuard 的 spawn 'error' 处理器空转，但已 return true → main 已返回 → 进程空转退出。
- 方案：spawn 后 `child.once('spawn', () => process.exit(0))`（确认启动后原进程退出）；`child.once('error', () => { /* 回退：继续原流程 */ return false 语义 })`——重构 relaunchAsGuard 返回 Promise<boolean>（成功 spawn 才 true），main 中 await。
- 落点：hub-exe.mjs relaunchAsGuard（async）+ launcher.mjs。
- 风险：spawn 确认机制（Node 'spawn' 事件）稳定。

### C3 单实例锁 TOCTOU
- 根因：lock.mjs 读-写非原子。
- 方案：`fs.openSync(file, 'wx')` 原子独占创建；EEXIST → 读 pid 判存活（现有逻辑复用）。
- 落点：lock.mjs acquireLock。
- 风险：低。

### C4 多实例检测只匹配 node.exe
- 根因：CIM 过滤 `Name='node.exe'`；dsh-hub.exe 运行的实例不可见。
- 方案：过滤改为 Name in (node.exe, dsh-hub.exe, dsh-hub-guard.exe) 且 CommandLine 匹配 dsh web/bin.js。
- 落点：multi-instance.mjs（A3 共享模块内）。
- 风险：低。
