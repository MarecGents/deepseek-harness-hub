## 1. 背景

上一轮（提交 58a0380）已修好壳自身 5 个文件 26 个图标名，组合器座位 `conversation.input.model` 恢复正常（CDP 实测 `_dshnms_*=8`、官方 `_7KE1Ra_*=0`、首屏供应商面板）。当时留下一项观察：

本轮目标两件事：**① 修掉该遗留缺陷；② 把本地领先的提交推上去、并入 PR #62。**

## 2. 根因分析（含上一轮推测的更正）

### 2.1 先排除官方 cordis

上一轮推测「注册者是官方 `dsh-client-ui-cordis`」。本轮核对（`lib/client.js`，72 KB）：

- 它从图元包取的成员是 `IconCheckOutlineRegular`、`IconCloseOutlineRegular`、`IconCodeOutlineRegular`、`IconCordisPluginOutlineRegular`、`IconInspectOutlineRegular`、`IconPlayOutlineRegular`、`IconStopFillRegular`、`IconTrashOutlineRegular`、`CodeBlock`、`DisclosureRow`、`StateDot`、`Tooltip`、`useDismissOnOutsidePointer`。
- 这 13 个成员在 0.1.7 图元包中**全部存在**（导出清单 265 项，其中图标 184 项）。

**结论：官方 cordis 无责，推测作废。**

### 2.2 真凶：`@modusensus/dsh-mneme@0.8.5`

| 项 | 事实 |
|---|---|
| 注册槽位 | `sidebar.footer.action`（list 插槽，与 dsh-context 并列） |
| 引用方式 | `const IconArchiveOutline20 = primitives.IconArchiveOutline20;` —— **模块级硬取，无回退** |
| 该名在 0.1.7 | **不存在**（`IconArchiveOutline20` 命中 = false） |
| 后果 | `IconArchiveOutline20 === undefined` → 渲染 `h(undefined, …)` → React #130 → 条目被 `reportEntryError(abdicate:true)` → 槽位显示 `data-slot-error` |

对照项 **`dsh-context@0.54.4`**（同槽位另一注册者）用的是双名回退，因此**不受影响**：

```js
const IconBranch = resolveIcon("IconBranchOutlineRegular", "IconBranchOutline16");
```

即：同一批改名，写法决定存活。`dsh-context` 自带兼容层，`mneme` 没有。

### 2.3 上游是否已修

| 包 | 已装版本 | npm latest | latest 发布时间 | 结论 |
|---|---|---|---|---|
| `@modusensus/dsh-mneme` | 0.8.5 | **0.8.5** | 2026-09-21 | 无新版可升 |
| `dsh-context` | 0.54.4 | 0.54.4 | 2026-09-22 | 无需处理 |

0.1.7-alpha.2 发布于 2026-09-22，晚于 mneme 0.8.5 的发布，故上游尚不知情。**不能靠升级解决。**

## 3. 方案设计

### 3.1 遗留缺陷：四条路径选型

| 方案 | 说明 | 判定 |
|---|---|---|
| **A. pnpm patch（profile 层）** | 写进 `~/.dsh/profiles/web/patches/`，重装后自动重放；与仓库**现有机制一致**（该 patch 已存在，当前用于适配 0.1.7 的 `tool/result` 格式） | **采用（持久层）** |
| B. 直接改 `.pnpm` 已装副本 | 立刻生效，无需 pnpm install | **采用（即时层，与 A 并用）** |
| C. 升级上游 | 0.8.5 已是 latest，无版本可升 | 不可行 |
| D. 壳侧 shim / 覆盖 | 引用发生在第三方插件模块内部，壳无法介入 | 不可行 |
| E. 上报上游 | 正确但不解决当下 | 记为后续项 |

**为何必须 A+B 并用**：patch 只在 `pnpm install` 时重放，而本项目铁律要求「改 profile 的 package.json/.npmrc 后必须在关 Hub 前提下跑完 install」。本轮不改依赖图，用 B 即时生效，用 A 保证下次重装不回归。

### 3.2 改动内容（最小、可回退）

```js
// 改前
const IconArchiveOutline20 = primitives.IconArchiveOutline20;
// 改后
const IconArchiveOutline20 = primitives.IconArchiveOutline20
  ?? primitives.IconArchiveOutlineRegular
  ?? primitives.IconArchiveOutline;
```

- 新名 `IconArchiveOutlineRegular` / `IconArchiveOutline` 在 0.1.7 中**均已核实存在**。
- 新组件签名 `({size = 16, className, strokeWidth})`，mneme 传的 `size: 15` 可透传，视觉等价。
- 三元回退保证：旧内核（有 20 名）→ 走原路径；新内核 → 走 Regular；将来再改名 → 退到无名版。

### 3.3 PR #62 合入路径

**现状**：PR #62 = `fix/0.1.7-and-subagent-sound` → `dev-v3`，state OPEN，`mergeStateStatus: CLEAN`。本地领先 origin **2 个提交**：

```
58a0380 fix(client): 图标导出名适配 0.1.7
7c86139 fix(client): 会话/工作区右键菜单关闭条件收紧   ← 见下方冲突
```

**冲突发现**：`7c86139` 是 `aba384c` 的 cherry-pick，而 `aba384c` 正是 **PR #61**（`fix/session-menu-dismiss` → `dev-v3`，OPEN，CLEAN）的唯一提交。两者 `src/` 内容完全一致（`git diff aba384c 7c86139 -- src/` 只余音效提交带入的 `session-runtime.ts`，与菜单修复无关）。

**为何当初必须 cherry-pick**：运行副本 `_up_/lib/client.js` 含该修复而分支源码没有，不补则重构建会**回退**已上线的行为。

**处置建议**（按优先级）：

1. **先合 PR #61，再 rebase 本分支丢弃 7c86139** —— 最终历史最干净，dev-v3 上该修复只出现一次。
2. 或者：直接 push 本分支（保留 7c86139），合 #61 时让 GitHub 以「内容相同」自动消解；#61 随即关闭。

无论哪条，**push 本分支都会自动更新 PR #62**（PR 跟踪的是分支而非提交）。
