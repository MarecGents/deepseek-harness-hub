# mg-dsh-desktop 桌面壳排错经验全记录

> 本文档沉淀 mg-dsh-desktop 从 0.1.7 到 0.1.8-rc.2 期间遇到的全部崩溃、配置陷阱与排错方法论。
> 适用于：桌面壳开发者、dsh 插件生态贡献者、遇到类似 WebView2 / Cordis 问题的排查者。

---

## 一、崩溃清单（5 种）

### 1. 窗口 3 秒自关闭

| 项目 | 内容 |
|------|------|
| **症状** | 窗口打开后约 3 秒自动消失，无报错 |
| **根因** | `dsh-hub` 出现在 web profile 的 `bundles` 列表中，其窗口生命周期与 mg-dsh-desktop 冲突——两个桌面壳插件同时创建 BrowserWindow，后加载的覆盖或销毁前者 |
| **排查线索** | `dsh.log` 中出现两次 `desktop shell opened`，或 Cordis loader 显示两个桌面壳 entry |
| **修复** | 从 web profile 的 `bundles` 列表中移除 `dsh-hub`；确保只有一个桌面壳插件被激活 |

### 2. 启动时插件树崩溃（JSON Schema）

| 项目 | 内容 |
|------|------|
| **症状** | `dsh web` 启动后立即退出，loader 报 Schema 验证错误 |
| **根因** | `dsh-memory` 插件的 JSON Schema 使用了 `required` 数组，而 dsh-tools DSL（Schemastery）不支持该字段 |
| **排查线索** | 启动日志中出现 `Schema validation failed` 或 `required is not supported` |
| **修复** | 从 bundles 中删除 `dsh-memory`；若需记忆功能，等上游修复 Schema 兼容性后重新启用 |

### 3. 启动时 `loadProfile` 抛错

| 项目 | 内容 |
|------|------|
| **症状** | `loadProfile` 阶段抛出异常，启动失败 |
| **根因** | `dsh-mode-boost` 缺少 `dsh.bundle.patch` 声明——Cordis loader 找不到 patch 行，尝试加载时出错 |
| **排查线索** | 日志中出现 `loadProfile` + `dsh-mode-boost` 相关错误 |
| **修复** | 从 bundles 中移除 `dsh-mode-boost`；或为其补上 `dsh.bundle.patch` 声明 |

### 4. 窗口空白/闪退（WebView2 E_ACCESSDENIED）

| 项目 | 内容 |
|------|------|
| **症状** | 窗口打开但内容空白，或打开后立即闪退；WebView2 初始化失败 |
| **根因** | WebView2 默认数据目录位于系统保护区（如 `Program Files` 或需要管理员权限的路径），导致 `E_ACCESSDENIED` |
| **排查线索** | Windows 事件查看器 → 应用程序日志中出现 `E_ACCESSDENIED` 或 `WebView2` 相关错误 |
| **修复** | 在 `src/desktop.ts` 中使用 `app.createWebContext({ dataDirectory })` 指定自定义数据目录到 `$DSH_HOME/<package-name>/browser-data` |
| **关键** | 数据目录路径必须用当前包名，不能复制其他项目的路径 |

### 5. "已在运行"但无窗口（僵尸进程锁滞留）

| 项目 | 内容 |
|------|------|
| **症状** | 启动时弹出"DeepSeek Harness Desktop 已在运行"，但没有可见窗口 |
| **根因** | 旧版本 launcher 用 `cmd /c "dsh.cmd"` 启动，留下 cmd.exe 僵尸进程——僵尸持有 `launcher.lock`，但实际 dsh 进程已退出 |
| **排查线索** | 检查 `$DSH_HOME/<package-name>/launcher.lock` 文件中的 PID；用 `tasklist /FI "PID eq <pid>"` 确认该进程是否存活 |
| **修复** | launcher.mjs 改用 `spawn(process.execPath, ...)` 直跳 Node.js，避免 cmd.exe 中间层 |
| **手动清理** | `taskkill /F /PID <pid>` + `rm ~/.dsh/<package-name>/launcher.lock` |

## 二、ZCode provider 配置陷阱

### 2.1 免费模型额度用完

| 项目 | 内容 |
|------|------|
| **症状** | 请求失败，返回额度超限 |
| **根因** | cherryin 免费模型额度耗尽 |
| **修复** | 换用 `deepseek/deepseek-v4-flash(free)`（独立额度池） |

### 2.2 图片发给不支持视觉的模型

| 项目 | 内容 |
|------|------|
| **症状** | 发送含图片的消息后模型返回错误或忽略图片 |
| **根因** | `modalities.input` 只配了 `["text"]`，宿主不会剥离图片，直接发给了纯文本模型 |
| **修复** | `modalities.input` 必须配 **`["text", "pdf"]`** |
| **关键技巧** | `"pdf"` 是触发宿主剥离图片的**关键字**——`supportsImages` 字段直接写无效 |
| **机制** | `vision_auto.py` hook 只负责注入文字描述，**不负责剥离图片**；图片剥离靠宿主根据 `modalities` 配置自动完成 |

## 三、跨问题通用教训

### 3.1 fork 补丁不 commit → git 操作一冲就丢

- **现象**：手动修改了源码但没有 commit，执行 `git checkout` / `git merge` / `git reset` 后修改被覆盖
- **丢失次数**：3 次
- **教训**：修改后立即 `git add && git commit`，哪怕是临时改动也先 commit 再说

### 3.2 锁滞留手动清理流程

```powershell
# 1. 找到锁文件中的 PID
cat ~/.dsh/<package-name>/launcher.lock

# 2. 确认进程是否存活
tasklist /FI "PID eq <pid>"

# 3. 强杀僵尸进程
taskkill /F /PID <pid>

# 4. 删除锁文件
rm ~/.dsh/<package-name>/launcher.lock
```

### 3.3 npm install 会清掉 SDK junction

- `build-client` 建立的 `@deepseek-ai/dsh-*` junction 会被 `npm install` 移除
- **必须**：装完依赖后重跑 `npm run build:client`

### 3.4 默认 npm registry 可能是华为云镜像

- 发布和验证必须显式 `--registry=https://registry.npmjs.org/`
- `npm view` 也可能拿到旧版本

## 四、排错方法论

### 4.1 诊断清单（按优先级）

1. **查 dsh.log**：`$PACKAGE_ROOT/dsh.log` 记录了启动全过程
2. **查 loader 状态**：loader entries 看 fiber 状态和 entry 列表
3. **查锁文件**：`$DSH_HOME/<package-name>/launcher.lock` 是否有存活 PID
4. **查 WebView2 数据目录**：确认路径可写、无权限冲突
5. **查 cordis.patch.yml**：disabled 门控是否正确、insert id 是否唯一
6. **查 bundles 列表**：web profile 的 `package.json` → `dsh.profile.bundles` 是否有冲突插件

### 4.2 崩溃恢复 SOP

```
1. taskkill /F /IM node.exe        # 杀所有 Node 进程（慎用）
2. rm ~/.dsh/<package-name>/launcher.lock
3. rm ~/.dsh/<package-name>/quit.marker
4. 检查 web profile bundles 列表
5. 重新启动桌面壳
```

### 4.3 插件冲突排查

```powershell
# 查看当前 bundles 列表
cat ~/.dsh/profiles/web/package.json | python -c "import sys,json; print(json.load(sys.stdin).get('dsh',{}).get('profile',{}).get('bundles',[]))"

# 查看 loader entries（在 dsh 运行时调用）
```
